# 中国工作日倒计时 · China Days Countdown

一个免费的 MIT 开源 Raycast 扩展，计算距离目标日期还有多少自然日或中国工作日，正确处理节假日和调休补班。

[下载版本](https://github.com/slzjw26/china-days-countdown/releases) · [安装与升级](docs/INSTALLATION.md) · [更新记录](CHANGELOG.md) · [反馈问题](https://github.com/slzjw26/china-days-countdown/issues)

首版为 **v0.1.0**，通过源码导入使用，尚未发布到 Raycast Store。

```text
准备向媳妇求婚    2026-09-25    9 工作日
```

示例以 **2026-09-14** 为今天，不计今天、计目标日；9/20 是补班日，9/25 是中秋假期。实际显示随今天日期变化。

## 安装（源码导入，无需 Raycast Pro）

要求 macOS、已安装并登录的 Raycast、**Node.js 22.22.2 或更新的 Node 22 LTS**、npm。本项目在 Raycast 1.104.29 环境构建；较旧客户端建议先更新。

1. 从 [Releases](https://github.com/slzjw26/china-days-countdown/releases) 下载源码 ZIP 并解压，在包含 `package.json` 的目录打开终端。也可克隆并选择首版标签：

   ```bash
   git clone https://github.com/slzjw26/china-days-countdown.git
   cd china-days-countdown
   git switch --detach v0.1.0
   ```

2. 安装依赖并启动开发导入：

   ```bash
   npm ci
   npm run dev
   ```

3. 在 Raycast 搜索 **查看倒计时**、**创建倒计时**。如果未出现，运行 Raycast 的 **Import Extension**，选择本项目目录，再运行 `npm run dev`。
4. 开发过程中保留终端运行，以便修改后自动编译。退出开发进程后，本地导入不会自动发布到 Store；后续编辑源码需要再次运行 `npm run dev`。

不安装到客户端、只验证源码：

```bash
npm test
npm run lint
npm run build
```

如果本机 Node 版本偏旧，也可临时使用匹配版本，不改系统 Node：

```bash
npm exec --yes --package=node@22.22.2 -- npm ci
npm exec --yes --package=node@22.22.2 -- npm run dev
```

`dist/` 是构建产物；源码安装应选择项目根目录。Release 提供源码 ZIP 和 `SHA256SUMS`，不是双击安装包。校验下载、更新版本和回退步骤见 [安装与升级](docs/INSTALLATION.md)。

## 使用

### 事件列表与表单

- **查看倒计时**：全宽列表展示名称、目标日期和剩余天数，已过期事件单独分组；回车打开独立详情，突出剩余天数，日期边界以图标、标签分组展示，计算区间合并展示且两端始终带完整年份。
- `⌘N` 新建；回车查看详情；`⌘E` 编辑；`⌘K` 查看操作；`⌘⌫` 删除，删除前有确认。
- 每个事件设置名称、可手输或从假期日历选择的 `YYYY-MM-DD` 目标日期、自然日/中国工作日、是否计入今天和目标日。
- 创建和编辑支持选填多行备注，最多 1000 字；只保存在本地。详情按纯文本展示，未填写时显示“暂无备注”。旧事件无需迁移，可直接编辑补充或清空备注。
- 详情正常时不重复显示计算规则或数据状态；只有假期信息不完整、更新失败时显示简短提示，来源和缓存详情在假期日历中查看。
- 目标日期、计算方式及日期选项右侧的 ⓘ 可悬停查看规则与快捷键。
- 默认：中国工作日、不计今天、计目标日。名称最多 80 个字符；支持 1900–2199 年的日期，未来倒计时最长 20 年。
- `⌘R` 手动刷新假期数据；「设置日期时区」可切换中国时间或系统时区。
- 列表打开时每分钟刷新，重新打开时重新读取。没有日历导入、通知、云同步或其他国家日历。

### 共用假期日历

- 创建或编辑页按 `⌘⇧D`（或 `⌘K → 从假期日历选择`）打开月历。回车选择并回填；Esc 返回不改日期，其他已填内容保留。
- 在事项详情回车打开同一个日历，可核对计数区间和每日计入原因，无需单独的计算明细功能。
- 紧凑单月，七列从周一排到周日；首尾用相邻月份日期补齐并淡化显示，也可直接选择。方向键选日，`⌘← / ⌘→` 切月，`⌘T` 回到今天；右上角选择年份，操作面板可直接选择月份。
- “休”为放假、“班”为调休补班；普通周末和假期使用红字、补班使用绿字。绿底“✓ 计入”、红底“− 不计”、灰底“区间外”区分计数状态，未知数据以黄色和“≈”标记。自然日模式的休息日仍显示红字，但参与计数时使用绿底。今天与目标日有边框和文字标记。休息日也可作为目标日。
- 选中日期查看当天说明，悬停日格可看完整说明；`⌘K` 可复制说明、查看当前月份所需年度的数据状态、缓存时间和国务院公告，`⌘R` 强制刷新。
- “假期未确认”表示数据缺失，相关工作日数显示估算。已有事项日历复用计算时的数据快照，主动刷新后一起更新。自然日计数不依赖假期数据，但打开日历时仍读取假期供参考。

### 菜单栏（可选）

在 Raycast 运行一次 **倒计时菜单栏**，或使用列表中的「启用菜单栏」。若 Raycast 提示开启后台刷新，请开启。

- 默认显示最近的未过期事件；日期相同按名称、ID 稳定排序。
- 在列表用「固定此事件到菜单栏」，或在菜单栏的「选择显示事件」中选择。
- 「自动：最近未过期事件」恢复自动选择；当前模式或固定事项前显示 **●**，已选项不可再次点击；已删除的固定事件会自动回退；固定的过期事件显示「已过期」。
- 每 5 分钟由 Raycast 调度刷新，编辑或固定后也会尝试立即刷新。电脑休眠、Raycast 未运行或后台刷新被禁用时无法准时更新，点击菜单或重新运行命令可刷新。
- 「隐藏菜单栏」隐藏显示，再运行菜单栏命令可恢复。也可以在 Raycast Settings → Extensions 禁用此命令及后台刷新。
- 状态示例：`准备向媳妇求婚 · 9 工作日`；`≈` 表示估算；`⚠` 表示更新失败且使用缓存。
- macOS 菜单栏空间不足时可能隐藏图标。

## 计算规则

1. 日期在 holiday-cn 中有显式记录：`isOffDay: false` 算工作日，`true` 不算。
2. 无显式记录：周一至周五算工作日，周末不算。
3. 自然日计数不需要下载假期数据；浏览假期日历时仍会下载。

默认区间为 **今天之后、目标日及之前**。两个包含选项独立作用；今天与目标日相同时，只有两个选项都开启才计一次。在工作日模式下，该日期仍需是工作日。过去事件的剩余数为 0，显示已过期。

默认按 `Asia/Shanghai` 确定今天，切换系统时区只改变「今天」的日期，中国工作日规则保持不变。日期运算使用日历日序号，不用两个本地零点的毫秒差，避免夏令时导致多算或少算一天。

## 数据来源、缓存与离线行为

使用 [NateScarlet/holiday-cn](https://github.com/NateScarlet/holiday-cn)（MIT），该项目自动抓取国务院公告。运行时下载公共年度 JSON：

- 主源：`https://raw.githubusercontent.com/NateScarlet/holiday-cn/master/{year}.json`
- 备用：`https://cdn.jsdelivr.net/gh/NateScarlet/holiday-cn@master/{year}.json`

每次请求最长 4 秒，主源失败尝试备用；年度下载最多 4 个并发。校验年份、日期、布尔值及冲突记录。相同年度成功结果缓存 24 小时，「刷新节假日数据」可强制更新。

公告按标题年份归档，下一年公告可能调整本年 12 月。因此区间涉及 12 月时会额外读取下一年，按公告年份顺序合并，后续年份记录覆盖较早记录。

| 情况                               | 行为                                   |
| ---------------------------------- | -------------------------------------- |
| 已缓存且 24 小时内                 | 直接使用本地数据                       |
| 缓存过期、更新失败                 | 保留已知假期；提示使用缓存             |
| 首次离线或年度尚未公布             | 未知日期按星期计算，明确标记估算       |
| HTTP 成功但 `papers` / `days` 为空 | 视为未公布；不会当作完整日历           |
| 上游从有效公告退化为空/坏数据      | 保留上次有效公告并提示更新失败         |
| 下一年公告未公布而区间涉及 12 月   | 保守标记估算，以覆盖尚未知晓的跨年调整 |

没有内置年度副本，首次离线仅能估算。未来年度数据会随上游发布和缓存刷新变为可用；2027 年等未公布年份不能保证精确。该工具按全国统一假期安排计算，不包含企业自定假期或个人请假。

## 本地数据与隐私

事件（含备注）与设置使用 Raycast **LocalStorage**，彼此独立保存；缓存也保存在此扩展的本地存储中。重启命令或 Raycast 不会主动清空它们。删除扩展或清除扩展数据可能丢失记录，MVP 暂无导出备份功能。

没有账号、服务器、遥测或付费 API。联网只请求相关年份的公共假期文件，不发送事件名称、备注和具体目标日期；公共托管方仍会收到常规 HTTP 请求信息，例如 IP 和所请求年份。

损坏的事件记录会提示但保留原始数据，不自动删除或覆盖。不同事件按独立键保存；同时编辑同一事件时最后一次保存生效。

## 开发与验证

```bash
npm ci
npm test                  # 日期、缓存、持久化、展示及发布工具
npm run lint              # ESLint、Prettier、TypeScript
npm run build             # 三个 Raycast 命令，输出 dist/
npm run lint:raycast      # 包括联网核查 Store author 的发布元数据校验
npm run dev               # 导入 Raycast 并监视源码
npm run check             # 依次执行测试、lint 与构建（与 CI 一致）
npm run release:check -- v0.1.0 # 核对版本和 CHANGELOG
node scripts/generate-icon.mjs  # 可选：重新生成已有图标
```

测试通过注入时钟、HTTP 边界和存储边界保持可重复，默认不联网。重点覆盖：补班/放假、周末兜底、同日四种组合、闰年、跨年、时区、过期事件、固定事件选择、缓存更新/失败、空公告/坏数据、本地持久化、不同事件同时保存及损坏记录保护。

`lint:raycast` 包含联网核查 Store 作者账号的步骤，当前本地开发标识尚未通过 Store 注册验证，不作为 GitHub CI 门槛。GitHub CI 会执行代码检查、类型检查、测试和构建。

主要结构：

```text
src/
  countdowns.tsx           列表与管理操作
  create-countdown.tsx     独立创建入口
  menu-bar.tsx            可选菜单栏
  components/
    event-form.tsx        创建/编辑与日期回填
    event-detail.tsx      完整事项详情
    holiday-calendar.tsx 共用选日与假期查看
  hooks/use-countdowns.ts 数据加载与刷新生命周期
  lib/
    dates.ts              日历日期与计数
    calendar.ts           月格与每日说明
    selection.ts          菜单选中状态
    presentation.ts       详情状态文案
    holidays.ts           假期下载、校验、缓存与状态
    model.ts              事件校验、排序、菜单选择
    repository.ts         按事件持久化
    snapshot.ts           列表和菜单共用的展示结果
    runtime.ts            Raycast API 适配
tests/                    Node test runner + tsx
```

手工验收：创建两个模式不同的事件 → 编辑日期包含选项 → 关闭并重开列表 → 固定/切换菜单事件 → 删除测试事件 → 核对估算提示。自动测试无法替代 Raycast 原生界面、菜单栏实际可见性及跨进程持久化验收。
